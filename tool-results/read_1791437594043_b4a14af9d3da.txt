     8→## 0. How to use this plan
     9→
    10→1. Copy this file into the project as `docs/PLAN.md`. Copy section 2 into the project as `docs/AGENT-BRIEF.md`. Create `docs/STATUS.md` from the template in section 7 and `docs/DECISIONS.md` as an empty log.
    11→2. Every loop, the agent starts from **only three things**: `docs/AGENT-BRIEF.md`, `docs/STATUS.md`, and the single task sheet it is about to work on (section 5). It does not re-read this whole plan, `WORK.md`, `DESIGN.md`, or the media folders. Keeping the first read small is the main way to protect the loop budget.
    12→3. Work the tasks in the order in section 5. Each task has an ID (for example `S2`). The agent writes the ID into `STATUS.md` when it starts and when it finishes.
    13→4. Brian answers the owner decisions in section 6 when the agent marks a task `BLOCKED-OWNER`. Nothing else needs Brian during a loop.
    14→
    15→### Assumed loop budget (calibrate this in loop 1)
    16→
    17→We do not have the exact GLM 5.3 harness limits, so this plan assumes the following and makes every number easy to change:
    18→
    19→- A loop ends after about **30 tool calls**, or earlier if the context gets long.
    20→- Tasks are sized **S** (up to 8 tool calls), **M** (up to 20), or **L** (not allowed; split it first).
    21→- One loop does **one M task, or up to two S tasks**, followed by its gate run and a status update.
    22→- After loop 1, the agent records the real tool-call count per task in `STATUS.md` under "Calibration". If the real numbers differ, edit `LOOP_TOOL_BUDGET` and the sizing rule in `docs/AGENT-BRIEF.md`. The task order does not change.
    23→
    24→If the harness cannot run shell commands at all, the agent must say so in `STATUS.md`, write the code and tests anyway, and list the exact gate commands for Brian to run. It must never write "tests pass" without output to back it up.

    62→## 2. AGENT-BRIEF.md (copy this file into the repo as `docs/AGENT-BRIEF.md`)
    63→
    64→```markdown
    65→# AGENT-BRIEF — Gabriel Homes production work
    66→
    67→You are working on a Django 5.x property site in this repo. Your job in this loop is
    68→the task(s) named in docs/STATUS.md under "Current loop". Do only that.
    69→
    70→## Read order (every loop)
    71→1. This file.
    72→2. docs/STATUS.md (current state, what is done, what is blocked).
    73→3. The task sheet for your task in docs/PLAN.md (section 5). Read only that section.
    74→Do NOT read: WORK.md, DESIGN.md, RUN-ME-FIRST.txt, db.sqlite3, anything under media/,
    75→property-images/, design-reference/, or static/fonts/. Use `grep -n` and `view` with a
    76→line range for other files.
    77→
    78→## Budget rules
    79→- LOOP_TOOL_BUDGET = 30 tool calls per loop. Keep a running count in STATUS.md.
    80→- Task sizes: S ≤ 8 tool calls, M ≤ 20. Work at most one M, or two S, per loop.
    81→- Pipe test output through tail. Example: `pytest -q 2>&1 | tail -15`.
    82→- Never print whole files you do not need. Never `cat` a file longer than 200 lines.
    83→- Use `find . -type f -not -path './media/*' -not -path './property-images/*' -not -path './static/*'` for listings.
    84→
    85→## Hard rules
    86→1. Only touch files listed in your task. If you need another file, write
    87→   "OUT-OF-SCOPE NEEDED: <path> because <reason>" in STATUS.md and stop that part.
    88→2. Security fixes: write the failing regression test FIRST, run it, see it fail,
    89→   then fix, then see it pass. Record both results.
    90→3. Never edit an existing migration. Add new migrations only.
    91→4. Never add a dependency unless the task says so. Pin exact versions in requirements.txt.
    92→   Any new dependency needs a DECISIONS.md entry with the reason.
    93→5. Never commit secrets. Never put a real password, key or token in code, docs or tests.
    94→   Demo passwords are allowed only in the dev launcher and README-dev text.
    95→6. Views stay thin. Business logic goes in models, querysets, or `services.py`.
    96→7. Never claim something passed unless you ran it. Paste the last 5 lines of the gate output
    97→   into STATUS.md. If you could not run it, write NOT RUN and why.
    98→8. If the same command fails 3 times with different fixes, stop the task. Mark it
    99→   BLOCKED-AGENT, paste the error excerpt (≤ 20 lines) into STATUS.md, and move on.
   100→9. Do not refactor or rename outside the task. Do not "tidy up" other code.
   101→10. Finish with: update STATUS.md (task status, gate output, calls used, next task),
   102→    then stop. Do not start the next task in the same loop unless the budget allows it.
   103→
   104→## Gate
   105→Run `bash scripts/gate.sh` before marking any task DONE. It must exit 0.
   106→If the gate fails on something outside your task, mark BLOCKED-AGENT with the output.
   107→
   108→## Stop conditions (write them, then stop)
   109→- Task DONE and gate green.
   110→- Task BLOCKED-AGENT (after rule 8).
   111→- Task BLOCKED-OWNER (needs an answer from section 6 of the plan).
   112→- Budget used ≥ 28 calls: finish the status update and stop.
   113→```

   117→## 3. Loop protocol
   118→
   119→Every loop follows the same steps. Keep to them even when a task looks easy.
   120→
   121→1. **Orient (≤ 3 calls).** Read `docs/AGENT-BRIEF.md` and `docs/STATUS.md`. Confirm the "Current loop" task. Run `git status --short` to check for uncommitted work from a previous loop. If there is uncommitted work, decide whether it belongs to the current task before doing anything else.
   122→2. **Plan (no tool calls).** Write three to six lines in the loop's STATUS entry: what will change, which files, which test proves it.
   123→3. **Test first, for security and bug tasks.** Add the regression test. Run it. Record the failure.
   124→4. **Implement.** Smallest change that makes the test pass. No drive-by edits.
   125→5. **Gate.** `bash scripts/gate.sh`. If it fails, fix within the task. Three failed attempts → BLOCKED-AGENT.
   126→6. **Commit.** `git add -A && git commit -m "<task-id>: <imperative summary>"`. One commit per task.
   127→7. **Record.** Update STATUS.md: task ID, status, gate tail, calls used, anything the next loop must know. Keep STATUS.md under 300 lines. Move old entries to `docs/STATUS-ARCHIVE.md` when it grows past that.
   128→8. **Stop.**

   207→### P1 — Security blockers
   208→
   209→Each task below is independent of the others in its phase unless it says otherwise. Each one needs its own loop.
   210→
   211→**S1 — Escape the JSON-LD (S)**
   212→- Why: D-XSS. A listing title can break out of the `<script>` tag.
   213→- Files: `apps/listings/views.py` (around lines 377–445), `templates/listings/detail.html` (around line 46), `apps/listings/tests/` (new file `test_security_xss.py`).
   214→- Test first: create a published property with title `</script><img src=x onerror=alert(1)>`. Request its detail page. Assert the raw string `</script><img` does not appear in the response body. Assert the JSON-LD block still parses as JSON and contains the title.
   215→- Fix: pass the dict itself into the context as `json_ld`. In the template, use `{{ json_ld|json_script:"listing-jsonld" }}` inside a `<script type="application/ld+json">` tag. Remove the `|safe`. Remove the `json_ld` line from the allowlist if present.
   216→- Done when: the test passes, G-SAFE passes with the allowlist empty, and the existing `test_json_ld_*` tests still pass.
   217→
   218→**S2 — Trust the real client IP (M)**
   219→- Why: D-RL. The client controls the first `X-Forwarded-For` entry.
   220→- Files: new `apps/core/clientip.py`, `apps/inquiries/views.py` (`_get_client_ip`), `apps/accounts/rate_limit.py` (`auth_rate_limit_key`), `config/settings/base.py` (new setting), `config/settings/prod.py`, `config/settings/dev.py`, `DEPLOY.md` (nginx block, handled in D4).
   221→- Design: add setting `TRUST_X_REAL_IP` (env, default False in base, True in prod). Nginx sets `X-Real-IP $remote_addr`, which the client cannot forge through the proxy. `get_client_ip(request)` returns `X-Real-IP` only when `TRUST_X_REAL_IP` is true. Otherwise it returns `REMOTE_ADDR`. Never read `X-Forwarded-For` for rate limiting.
   222→- Tests first: (a) with TRUST_X_REAL_IP off, rotating `X-Forwarded-For` values do not reset the enquiry limit; (b) with TRUST_X_REAL_IP on, `X-Real-IP` determines the bucket; (c) auth login hit six times from one IP with rotating `X-Forwarded-For` returns 429 on the sixth.
   223→- Done when: all three tests pass, and both limiter call sites use `get_client_ip`.
   224→
   225→**S3 — Shared rate-limit store (S)**
   226→- Why: D-CACHE.
   227→- Files: `config/settings/prod.py`, `config/settings/dev.py`, `apps/accounts/rate_limit.py` (docstring is wrong: it says "DB-backed LocMemCache"; fix the wording).
   228→- Steps: in prod, set `CACHES["default"]` to `django.core.cache.backends.db.DatabaseCache` with `LOCATION = "gabriel_cache"`. Add `createcachetable` to the DEPLOY steps (D4). Keep LocMem in dev. Do not add Redis (it would be a new service).
   229→- Test: under prod settings, `caches["default"]` is a DatabaseCache. Auth limiter state survives a second cache handle in the same test.
   230→- Done when: the test passes and the docstring is accurate.
   231→
   232→**S4 — Demo credentials never reach production (S)**
   233→- Why: D-CRED, D-LAUNCH.
   234→- Files: `scripts/setup_accounts.py`, `START-GABRIEL-HOMES.bat`, `START-GABRIEL-HOMES.command`, `START-GABRIEL-HOMES.sh`, `apps/listings/management/commands/seed_demo.py`, new `apps/core/tests/test_demo_guards.py`.
   235→- Steps:
   236→  1. `setup_accounts.py` refuses to run if `settings.DEBUG` is False and prints a clear message. It sets a password only when it creates the account. It never resets an existing password.
   237→  2. Demo passwords stay as they are for the local launcher. The launcher still gets working demo logins on a fresh copy, because the account is created on first run.
   238→  3. Remove the "Safe to run on every start" sentence from the docstring.
   239→  4. Delete `db.sqlite3` from the zip deliverable. The demo database is rebuilt by the launcher.
   240→- Tests first: (a) with `DEBUG=False`, `setup_accounts` raises or exits without changing any user; (b) with an existing admin whose password was changed, running setup leaves the password unchanged.
   241→- Done when: both tests pass and the launcher still starts on a clean copy (checked manually by Brian; mark O-DEMO in STATUS).
   242→
   243→**S5 — Production refuses unsafe configuration (S)**
   244→- Why: D-KEY, D-DB.
   245→- Files: `config/settings/base.py`, `config/settings/prod.py`, new `apps/core/tests/test_prod_config.py`.
   246→- Steps: in `prod.py`, raise `ImproperlyConfigured` when `SECRET_KEY` is missing, starts with `dev-insecure`, or is shorter than 50 characters. Raise when `ALLOWED_HOSTS` is empty. Raise when `DATABASE_URL` is empty or does not start with `postgres`. Keep the dev default key in base only for dev.
   247→- Tests: run a subprocess with each bad environment and assert a non-zero exit with the expected message. Run once with a good environment and assert success.
   248→- Done when: the tests pass and `make deploy-check` (after D6) still works with a dummy postgres URL.
   249→
   250→**S6 — Use STORAGES, so hashed static files are active (S)**
   251→- Why: D-STATIC.
   252→- Files: `config/settings/base.py` (line with `STATICFILES_STORAGE`), `config/settings/dev.py`, `config/settings/prod.py`.

In dev, use `StaticFilesStorage` for staticfiles so runserver does not need collectstatic.

On success, set `email_sent_at`. On failure, set `email_error`, log with `logger.exception`, and still return the success partial to the visitor.    274→**S10 — Content-Security-Policy and self-hosted map library (M)**
   275→- Why: D-CSP.
   276→- Steps:
   277→  1. Download Leaflet 1.9.4 JS and CSS into `static/vendor/leaflet/`. Record the exact source URL and SHA-256 in DECISIONS.md. Do not add an npm dependency.
   278→  2. Replace the unpkg `<script>` and `<link>` in the listing template with local `{% static %}` references. Keep the Leaflet integrity attributes only if they still match the local file, otherwise remove them.
   279→  3. Add `apps/core/middleware.py` with `ContentSecurityPolicyMiddleware`.    460→## 8. Failure modes and how to handle them
   461→
   462→| Failure | Sign | Response |
   463→|---|---|---|
   464→| Looping on one error | Same command fails three times | Rule 8 of the brief: BLOCKED-AGENT, record excerpt, move on. |
   465→| Scope creep | Diff touches files outside the task | Revert the extra files. Log OUT-OF-SCOPE NEEDED. |
   466→| False "done" | Status says DONE with no gate output | Reopen the task. The gate tail is mandatory. |
   467→| Context loss between loops | Agent re-discovers the codebase | Improve STATUS.md, not the chat. Next loop reads STATUS first. |
   468→| Burning budget on reads | Many views of large files | Use `grep -n` and line ranges. Never open media or the DB. |
   469→| Migration conflicts | Edited an old migration | Revert it. Create a new migration. |
   470→| Test flakiness on time | Random failures near midnight or timezone | Freeze time in the test. Note it in DECISIONS.md. |
   471→| Manifest static errors in tests | "Missing staticfiles manifest entry" | Tests use dev settings. Only G-STATIC uses prod settings and runs `collectstatic` first. |
   472→| Dependency pulled in silently | requirements.txt changes without a DECISIONS entry | Revert, or record the decision. |
   473→| Visual drift | Pages look generic | Not a code gate. Logged in V2 with screenshots. Fixing it is a new task. |
