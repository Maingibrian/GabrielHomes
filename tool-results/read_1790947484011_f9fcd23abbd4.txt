     7→## 1. Mission
     8→
     9→Build **Gabriel Homes**, a Kenyan property-listings portal (buy / rent) in **Django**. It follows the *structure and user experience* of established Kenyan listing portals such as buyrentkenya.com (reference page pattern: `/flats-apartments-for-sale/mombasa`): search-first homepage, filterable results pages with SEO-friendly URLs, rich listing pages, agent contact via call / WhatsApp / enquiry form.
    10→
    11→**Visual design is fixed:** the look and feel must match the Framer-built Gabriel Homes brochure site supplied in `design-reference/index.html`. The full extracted spec is in section 10 and in `DESIGN.md`. The portal functionality (search, listings, agents) is new, but it must be dressed in that same design language so it reads as one product.
    12→
    13→Primary markets for seed data and defaults: **Mombasa, Nairobi, Kilifi, Kwale (Diani), Kiambu, Kajiado (Ngong, Kitengela)**. Currency: **KES**. Phone format: **+254**.
    14→

    78→## 6. Data model (v1)
    79→
    80→**Location**
    81→- `name`, `slug`, `parent` (self FK, null), `level` (`county` | `area` | `neighbourhood`), `lat`, `lng`
    82→- Unique slug per parent. Method `get_descendants()` and `full_path()`.
    83→
    84→**PropertyType**
    85→- `name` (e.g. "Flats & Apartments"), `slug_plural` (e.g. `flats-apartments`), `slug_single` (e.g. `apartment`), `is_residential`, `is_commercial`, `is_land`
    86→- Seed: flats-apartments, houses, townhouses, maisonettes, bungalows, villas, land, commercial-property, offices, shops, warehouses.
    87→
    88→**Amenity** — `name`, `icon` (string key), `category` (security, utilities, lifestyle, building).
    89→
    90→**Property**
    91→- `title`, `slug` (unique), `description`
    92→- `listing_type`: `sale` | `rent`
    93→- `property_type` FK, `location` FK (leaf location), `address_text` (optional, public-safe), `lat`, `lng`
    94→- `price` (Decimal, KES), `price_period` (`total` for sale, `monthly` for rent), `price_negotiable` (bool)
    95→- `bedrooms`, `bathrooms`, `size_sqm` (nullable), `land_size_acres` (nullable)
    96→- `furnishing` (`unfurnished` | `semi` | `furnished`), `parking_spaces`, `year_built` (nullable), `service_charge` (nullable)
    97→- `amenities` M2M
    98→- `agent` FK to `AgencyProfile`, `status` (`draft` | `published` | `under_offer` | `sold_let` | `archived`)
    99→- `is_featured`, `is_verified`, `views_count`
   100→- `created_at`, `updated_at`, `published_at`
   101→- Indexes: (`status`, `listing_type`, `property_type`, `location`), `price`, `published_at`.
   102→
   103→**PropertyImage** — `property` FK, `image`, `caption`, `position`, `is_cover`. Enforce one cover per property.
   104→
   105→**AgencyProfile** — `user` OneToOne, `name`, `slug`, `logo`, `bio`, `phone`, `whatsapp`, `email`, `website`, `office_location` FK, `is_verified`.
   106→
   107→**Inquiry** — `property` FK, `name`, `email`, `phone`, `message`, `status` (`new` | `read` | `replied`), `created_at`, `user` FK (nullable). Spam control: honeypot field + per-IP rate limit.
   108→
   109→**SavedProperty** — `user`, `property`, unique together.
   110→
   111→**SavedSearch** (model only in v1, alerts are "Later") — `user`, `name`, `querystring`, `created_at`.
   112→
   113→Add a `PropertyQuerySet.published()` and use it everywhere on the public site. Draft or archived listings must never appear publicly.

   115→## 7. URL map
   116→
   117→SEO-friendly search URLs are a core feature. Pattern:
   118→
   119→```
   120→/                                                     home
   121→/<type-plural>-for-sale/                              e.g. /flats-apartments-for-sale/
   122→/<type-plural>-for-sale/<location-slug>/              e.g. /flats-apartments-for-sale/mombasa/
   123→/<type-plural>-for-rent/<location-slug>/              e.g. /houses-for-rent/nairobi/
   124→/property-for-sale/<location-slug>/                   all types in a location
   125→/property-for-rent/<location-slug>/
   126→/listing/<slug>-<id>/                                 property detail
   127→/agents/                                              agent directory
   128→/agents/<agency-slug>/                                agency profile + their listings
   129→/account/                                             login, signup, profile (allauth)
   130→/account/saved/                                       saved properties
   131→/dashboard/                                           agent dashboard (login + agent role)
   132→/dashboard/listings/new/ | <id>/edit/ | <id>/images/
   133→/dashboard/inquiries/
   134→/about/  /contact/  /privacy/  /terms/
   135→/sitemap.xml  /robots.txt
   136→```
   137→
   138→Filter query params on search pages: `?q=&min_price=&max_price=&beds=&baths=&furnishing=&amenities=&sort=&page=`.
   139→Sort options: `newest` (default), `price_asc`, `price_desc`, `featured`.
   140→Canonical URL for filtered pages = the clean path without query params.

   179→## 9. Search and filtering spec
   180→
   181→- Implement with `django-filter` `FilterSet` on `Property`, with the location filter including **descendants** (searching "Nairobi" includes Westlands, Kilimani, etc.).
   182→- Free-text `q` searches title, description, location name (use PostgreSQL full-text search where available; fall back to `icontains` on SQLite).
   183→- Price filters use KES. Show formatted values (`KES 12,500,000`; rent shows `/month`).
   184→- All queries use `select_related` / `prefetch_related` to avoid N+1. Add a test that asserts the query count for the results page stays under a fixed number.

   186→## 10. Design system (extracted from the Framer reference)
   187→
   188→Source: `design-reference/index.html`. Values below were read from the file's CSS. Items marked *(inferred)* were deduced from layer names or copy and must be checked against the reference.
   189→
   190→**Character:** warm, editorial, premium. Earthy espresso and cream palette, tight tracking, large confident headlines, generous whitespace, soft shadows, pill buttons, big rounded cards, subtle motion.
   191→
   192→### 10.1 Colour tokens
   193→```css
   194→:root{
   195→  --cream:    #faf8f4;  /* page background, light sections */
   196→  --white:    #ffffff;
   197→  --sand:     #d8c9b8;  /* soft borders, chips, subtle fills */
   198→  --taupe:    #8a7d70;  /* muted text, divider lines */
   199→  --clay:     #a66a4d;  /* secondary accent */
   200→  --brown:    #5a4032;  /* hover / secondary dark */
   201→  --espresso: #2a211c;  /* main dark background (agents, CTA, footer) */
   202→  --ink:      #211e1b;  /* body text on light */
   203→  --burnt:    #af4715;  /* primary accent: key CTAs, highlights */
   204→}
   205→```
   206→Ignore the purple/navy values in the Framer file (`#886bff`, `#0a0f23`); they are unused Framer defaults. White text sits on photos and espresso. Dark ink sits on cream.
   207→
   208→### 10.2 Typography
   209→- Families: **Geist** (UI and headings), **Geist Mono** (small labels and tags). Self-host both. A second sans (Satoshi) appears in the file once; do not use it.
   210→- OpenType features on body: `font-feature-settings: "blwf" 1, "cv03" 1, "cv04" 1, "cv09" 1, "cv11" 1;`
   211→- Weights: 500 for headings and UI emphasis, 400 body, 300 for occasional light display text.
   212→- Line-height: `1.2` for headings, `1.3` for body copy.
   213→- Tracking is tight everywhere (used values: `-0.02em`, `-0.03em`, `-0.04em`, `-0.05em`, `-0.08em`):
   214→  - Display wordmark (footer "Homes", 120px): `-0.08em` *(inferred)*
   215→  - H1 (64–80px): `-0.05em`
   216→  - H2 (48px): `-0.04em`
   217→  - H3 (28–36px): `-0.03em`
   218→  - Body and UI (14–20px): `-0.02em`
   219→- Size scale seen in the file: 10, 12, 14, 16, 18, 20, 22, 24, 28, 36, 40, 48, 51, 64, 80, 120px. Use `clamp()` so sizes shrink on mobile.
   220→- Section tags in square brackets, uppercase, small mono *(inferred)*: `[STORY]`, `[NUMBERS]`, `[AGENTS]`, `[PHILOSOPHY]`, `[FOOTER]`, `[001-UNDERSTAND]`. Paired with a one-word eyebrow (VISION, MILESTONES / IMPACT, EXPERTS, PRINCIPLE / DIFFERENCE).
   221→- Index numbers (`01`, `[001]`) label cards, nav links, and steps.
   222→
   223→### 10.3 Shape, depth, lines
   224→- Radii: `8px` (inputs, small chips), `20px`, **`40px` (cards, image frames)**, **`100px` (pill buttons and tags)**, full circle for avatars.
   225→- Shadows are very soft and layered. Card: `0 0.6px 1.57px -1.5px rgba(0,0,0,.17), 0 2.29px 5.95px -3px rgba(0,0,0,.14), 0 10px 26px -4.5px rgba(0,0,0,.02)`. Button: `0 2px 4px rgba(0,0,0,.1), 0 1px 0 rgba(0,0,0,.05), 0 0 0 1px rgba(255,255,255,.15)`.
   226→- Outlined button: `box-shadow: inset 0 0 0 1px #000` (1px inner outline).
   227→- Nav glass: `backdrop-filter: blur(10px)` on a dark translucent bar (`rgba(34,34,34,.8)`).
   228→- Photo overlays: vertical black gradients (transparent to dark) behind white text on photos.
   229→- Dividers: 1px lines in `--taupe`.
   230→- One image in the file uses `filter: grayscale(1)` *(likely the team portraits; check whether it colourises on hover)*.
   231→
   232→### 10.4 Layout and breakpoints
   233→- Desktop `≥1200px`, tablet `810–1199px`, mobile `≤809px`. Build mobile-first and add `min-width: 810px` and `min-width: 1200px` queries.
   234→- Alternating light (cream) and dark (espresso) sections. Wide gutters, large vertical padding between sections.
   235→- Header has three states: desktop bar, tablet bar, mobile hamburger with full-screen menu ("Menu" / "Close").
   236→
   237→### 10.5 Components to build (reuse across the whole site)
   238→Pill button (primary burnt, dark espresso, outlined, with arrow icon that slides on hover), nav link with index number, section tag + eyebrow, stat block (animated number + label + taupe line), value card, numbered principle card, agent portrait card, listing card (40px radius, cover image, index tag, price in 500 weight), search bar (pill), newsletter field with Subscribe, footer link columns, giant footer wordmark, full-screen mobile menu, thin divider line.
   239→
   240→### 10.6 Motion (all optional enhancements, all disabled under `prefers-reduced-motion`)
   241→- **Smooth scrolling:** Lenis (open source), loaded from a pinned CDN build or self-hosted.
   242→- **Animated number counters** for stats (e.g. 480+, 98%, 12+, 1.4B+). Vanilla JS with `IntersectionObserver`, count up once when visible.
   243→- **Word-by-word scroll reveal** for the founder quote (split into word spans, fade/colour in as the block scrolls into view).
   244→- **Staggered text cycle / split-letter animation** for nav labels and the footer "Homes" wordmark (per-letter spans with staggered transitions).
   245→- **Appear-on-scroll** fades and small upward slides for cards and sections.
   246→- **Hover:** arrow slides inside the pill button, links underline, cards lift slightly.
   247→- Icons: Phosphor icon set (inline SVG sprite, only the icons used).
   248→- Performance budget: motion must never block content. All text is readable without JS.
   249→
   250→### 10.7 Imagery
   251→- Large, warm, light-filled architectural and interior photography for hero and cards; portraits for the team.
   252→- The reference uses Unsplash/Pexels URLs. Do not hotlink in production: download images locally, convert to WebP, add `srcset`, and replace with the owner's own photography as it becomes available.
   253→
   254→### 10.8 Mobile and bandwidth
   255→Most Kenyan users browse on phones over variable connections. Keep the motion above as progressive enhancement, lazy-load all below-the-fold images, set explicit image dimensions, and keep JS small. Contact actions (Call, WhatsApp) stay thumb-reachable (sticky bottom bar on listing pages). Accessibility: semantic HTML, visible focus, AA contrast (check white text over photos and `--burnt` on `--cream`).
