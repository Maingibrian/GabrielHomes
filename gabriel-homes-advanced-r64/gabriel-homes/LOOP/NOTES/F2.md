# NOTES/F2.md — capability gate (attempts: 1 failed, fixed same run)

## Failed attempt 1 — end-gates went red (12 failures), r16
**Symptom:** first end-of-run `pytest -q`: 12 failed / 520 passed. All failures
were template-comment-leak guards (test_p0_three_state_harness,
test_p1_agents_redirect comment-leak, test_phase2_home comment-leak).

**Root cause:** the r16 builder wrote a THREE-LINE `{# … #}` comment in
templates/base.html above the fx-gate.js tag. Django's `{# #}` syntax does not
span multiple lines — the lexer only strips the single-line form, so the raw
comment text rendered onto every page that extends base. This is a KNOWN bug
class in this repo: run 4 hit it on /agents/ and added guard tests
(test_phase2_home.py::test_no_template_comment_leaks_into_html and the
three-state harness) — which is exactly what caught it within one gate run.

**Fix:** comment reduced to one line (base.html line 68). Affected modules
re-run green; full suite 532 passed.

**Rule for the next builder (do not repeat):** in templates/, `{# … #}` comments
must fit on ONE line; use `{% comment %}…{% endcomment %}` for anything longer.
Grep template edits for a `{#` whose `#}` is not on the same line before
committing.

## r58 — hardware proxies removed (owner report: bento animation dead)

**Symptom:** owner reported "the animation of expanding cards is broken"
twice (r56/r57 era). The bento shape-shift, cursor polish and hero video
were fine in code — verified live (promote/switch/reset all run when the
gate passes) — but never ran on the owner's machine.

**Root cause:** the F2 gate demoted any device reporting <= 4 CPU cores
or <= 4 GB memory to "lite", and bento-shift.js hard-requires
data-fx="rich". Chrome's navigator.deviceMemory is rounded DOWN to the
nearest power of two and capped at 8, so every 4-7 GB laptop reports 4;
4-core laptops are most of the market. The owner's machine was silently
"lite" — hover did nothing. The r57 image fix was real but unrelated;
the animation complaint persisted because testing in the 2-core sandbox
required forcing the gate attributes, which masked the real defect.

**Fix:** computeFx now reads only visitor-chosen signals —
prefers-reduced-motion (none) and Save-Data (lite). The proxies are gone
from the JS (pinned by test_fx_gate_has_no_hardware_proxies, which
asserts the identifier strings never reappear in the file) and the
mirror table. DECISIONS.md keeps the historical D-LOOP-33a entry.

**Lesson:** test the REAL script path end-to-end (fx-gate.js executing,
not forced attributes) before declaring an animation fixed. Capability
proxies that round down will demote your best customers.
