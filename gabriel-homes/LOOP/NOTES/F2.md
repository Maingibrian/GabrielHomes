# NOTES/F2.md — capability gate (attempts: 1 failed, fixed same run)

## Failed attempt 1 — end-gates went red (12 failures), r16
**Symptom:** first end-of-run `pytest -q`: 12 failed / 520 passed. All failures
were template-comment-leak guards (test_p0_three_state_harness,
test_p1_agents_redirect comment-leak, test_phase2_home comment-leak).

**Root cause:** the r16 builder wrote a THREE-LINE `{# … #}` comment in
templates/base.html above the fx-gate.js tag. Django's `{# #}` syntax does not
span multiple lines — the lexer only strips the single-line form, so the raw
comment text rendered onto every page that extends base. This is a KNOWN bug
class in this repo: run 4 hit it on /agents/ and added guard tests
(test_phase2_home.py::test_no_template_comment_leaks_into_html and the
three-state harness) — which is exactly what caught it within one gate run.

**Fix:** comment reduced to one line (base.html line 68). Affected modules
re-run green; full suite 532 passed.

**Rule for the next builder (do not repeat):** in templates/, `{# … #}` comments
must fit on ONE line; use `{% comment %}…{% endcomment %}` for anything longer.
Grep template edits for a `{#` whose `#}` is not on the same line before
committing.
